# WordPress translation workbench: es_ES

Working repository of the Spanish (Spain) team for translating and reviewing WordPress strings on [translate.wordpress.org](https://translate.wordpress.org/locale/es/default/) with AI help.

The repository is meant to be cloned by other locale teams: file names, code and project documentation are in English; everything specific to the language (style guide, glossary, translation memory, review notes) is in that language. The product is two installable skills (`wordpress-translator-es/`): one translates and one reviews, a `.po` in and a `.po` out, with the locale's whole style guide and glossary inside. Workflows are built on top of them, like the GlotPress one for moderators (`wordpress-polyglots-es/`). Shared guidelines for all locales may later move to a multi-locale repository.

## Subprojects

| Folder | Subproject | Status |
|---|---|---|
| `review/` | Fast review of *waiting* strings: we receive the waiting `.po`, return only the strings that need changes, approve the rest | Active, top priority |
| `polyglots/` | Tuning the `polyglots` tool (ada.tools): rules file, calibration log, local models with Ollama | Active, fed by `review/` |
| `wordpress-translator-es/` | Base plugin: skills `translate` and `review` (a `.po` in, a `.po` out, with the whole style guide and glossary inside, nothing else) | First version |
| `wordpress-polyglots-es/` | Workflow plugin for moderators, on top of the base: GlotPress download, precheck, split, import URL (`translate-glotpress-project`, `review-glotpress-waiting`) | First version |
| `skill/` | Development of both plugins: scripts (`po_tool.py`, `glotpress.py`, `dev_tools.py`), `package.py` (regenerates the plugins from `resources/`) and `benchmark-log.md` | Active, fed by `review/` |
| (separate repo) | Common strings: most repeated strings across core, plugins and themes, translated once and applied first | Planned; only its output `.po` will come here |

Shared locale resources are in `resources/`. How the subprojects feed each other is in [docs/workflow.md](docs/workflow.md); what is going on right now is in [docs/status.md](docs/status.md).

## Layout

```
docs/          project documentation (English)
resources/     locale resources (Spanish): style guide, glossary, translation memory, moderation guide
review/        review workflow and scripts
bench/         test bench: reference cases reviewed by a human, and results
rounds/        review rounds, one folder each (ignored by git)
dist/          packaged skill zip (ignored by git)
polyglots/     rules/ (generated rules file, build script, tests), calibration log, local-models/
skill/         plugin development: scripts, package.py, benchmark log
wordpress-translator-es/  base plugin: skills/<name>/SKILL.md by hand, references/ generated by skill/package.py
wordpress-polyglots-es/   workflow plugin: skills/<name>/SKILL.md by hand, scripts/ generated by skill/package.py
.claude-plugin/ marketplace file, so the repository can be added as a plugin marketplace
```

## Installing

Claude Code:

```
/plugin marketplace add nilovelez/wp-es-polyglots
/plugin install wordpress-translator-es@wp-es-polyglots
/plugin install wordpress-polyglots-es@wp-es-polyglots   # optional: GlotPress workflow for moderators
```

The workflow plugin needs the base plugin. Or with the zips that `python3 skill/package.py` writes to `dist/`: `wordpress-translator-es.zip` and `wordpress-polyglots-es.zip`.

claude.ai (web or desktop app): it takes one skill per zip, so `package.py` also zips the two base skills alone (each one is self-contained): `dist/claude-ai/wordpress-translate-es.zip` and `dist/claude-ai/wordpress-review-es.zip`. Turn on code execution in Settings → Capabilities and upload them under Skills. There you give Claude the `.po` file; downloading from translate.wordpress.org depends on the network access of the sandbox, so the workflow plugin is for Claude Code.

| Skill | Plugin | Input → output |
|---|---|---|
| `translate` | base | `.pot` / `.po` → translated `.po` |
| `review` | base | translated `.po` → `.po` with only the strings to change |
| `translate-glotpress-project` | workflow | translate.wordpress.org URL → download, `translate`, the `.po` to import |
| `review-glotpress-waiting` | workflow | translate.wordpress.org URL → download, check whether the batch deserves a review, `review`, the `.po` to import |

They need Python 3 and never upload or approve anything.

## Cloning for another locale

1. Replace the contents of `resources/` with your locale's style guide, glossary export and translation memory.
2. Empty `skill/benchmark-log.md` and `polyglots/calibration-log.md`.
3. Regenerate `polyglots/rules/<locale>.base.yaml` with the tool's rules generator and adapt the `M` and `P` lists in `build_rules.py`.
4. Update `CLAUDE.md` and the locale-specific parts of the skills' `SKILL.md` files and the scripts (locale code, Spanish quotes and typography checks, the locale in GlotPress URLs), rename the plugin folders, and run `python3 skill/package.py`.
